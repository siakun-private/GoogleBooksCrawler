# 추출과 EPUB 생성 구조

핵심은 리더에 이미 로드된 분할 전 본문을 보존하는 것입니다. 흐름은 `browser.py`의 연결, `extract.py`의 수집 및 로컬 참조 변환, `build_epub.py`의 검증과 패키징으로 나뉩니다. HTML 읽기 화면은 별도로 생성하며 EPUB 안에 앱 코드를 넣지 않습니다.

## 로그인된 탭 연결

`Browser`는 Orca CLI의 탭 목록에서 요청한 Google Books 책 URL을 찾습니다. 같은 책이 여러 탭에 있으면 임의로 고르지 않습니다. 현재 Orca 프로세스가 연 루프백 포트를 조사하고 각 `/json/list`가 가리키는 대상 URL을 확인해 탭 전용 CDP 연결을 찾습니다. 프록시가 없으면 해당 탭의 네트워크 기능을 초기화한 뒤 다시 찾습니다.

Google의 본문은 `books.googleusercontent.com`의 OOPIF로 실행될 수 있습니다. 일반적인 iframe 선택이 실패하더라도 프레임이 없다고 결론 내리지 않습니다. `Target.setAutoAttach`를 재설정하고 Runtime 컨텍스트를 활성화해 실제로 붙은 본문 세션을 사용합니다. 메인 문서와 본문 세션은 서로 다른 실행 대상입니다.

명시적인 `--cdp`도 루프백 주소와 실제 책 URL을 검사합니다. 포트나 탭 ID를 소스에 고정하거나 다른 Chrome의 디버거를 임의로 사용하지 않습니다. 저장한 계정 쿠키를 requests에 옮기는 방식도 사용하지 않습니다.

## 메타데이터와 완전한 본문

`bootstrap()`은 메인 문서의 `reader.start(...)`에서 JSON 부분을 파싱합니다. JavaScript 전체를 Python 코드처럼 실행하지 않습니다. 책 ID와 판본을 검증하고 서버 메타데이터의 구간 순서를 따릅니다.

`scan_segments()`는 본문 세션에서 `HTMLDivElement.prototype`의 객체를 조회합니다. 연결이 끊긴 DOM 객체도 포함되므로 화면에 없는 원본 구간을 찾을 수 있습니다. 클래스가 정확히 `gb-segment`이고 `ocean-sliced-element`가 없는 구간만 후보로 삼으며 첫 GBS 앵커로 식별합니다. 같은 앵커의 후보가 여러 개면 더 긴 본문을 유지합니다. 화면 페이지를 나타내는 분할 객체를 후보에 섞지 않습니다.

구간 이동에는 `start_position`을 사용합니다. 구간이 이전 페이지의 끝 앵커에서 시작할 수 있으므로 시작 페이지 번호만으로 목적지를 만들면 특정 구간을 찾지 못합니다. 브라우저 주소의 `pg`를 바꾸고 리더에 위치 변경을 알린 뒤 기대한 구간이 로드되는지 기다립니다.

임시 Map은 추출 중 분할 전 객체가 없어지지 않도록 붙잡는 용도입니다. 객체 그룹과 임시 참조는 작업 후 정리하고 읽던 위치로 돌아갑니다. 클래스나 메타데이터 구조가 달라졌으면 수집 조건을 다시 확인하며 보이는 조각만 저장해 성공 처리하지 않습니다.

## 리소스와 참조

이미지와 글꼴은 로그인된 브라우저 안에서 가져옵니다. Google Books의 HTTPS 자산은 메인 문서에서, Blob과 data 자산은 본문 세션에서 읽습니다. 선택한 책 외부를 가리키는 임베디드 자산은 거부합니다. 단순한 외부 참고 링크는 콘텐츠 의존성과 구분합니다.

이미지는 Pillow로 실제 형식과 정상 디코딩 여부를 확인한 뒤 원래 바이트를 저장합니다. 글꼴 확장자는 파일 시그니처로 결정합니다. 이름에 해시를 붙여 충돌을 피하고 보고서에는 바이트 수, 이미지 크기와 SHA-256을 남깁니다. CSS의 글꼴 주소와 SVG의 `xlink:href`도 로컬 경로로 바꿉니다.

출판사 CSS의 리더 전용 범위를 `.book-content`로 바꾸고 고정 페이지 크기는 EPUB 앱이 다시 배치할 수 있게 조정합니다. 모든 문서의 앵커를 수집한 다음 목차, 원본 페이지 목록과 장 사이 각주를 연결합니다. 정확한 위치 앵커가 없을 때는 같은 원본 페이지 앵커로 제한적으로 대체하며 페이지마저 없으면 실패합니다.

XML의 텍스트와 JavaScript `textContent.length`를 대조할 때는 UTF-16 코드 단위를 사용합니다. Python `len()`만 비교하면 보조 평면 문자가 있는 책에서 기준이 달라집니다. 원본 페이지 앵커 누락도 별도로 검사합니다.

## 재개와 패키징

완료된 구간과 자산은 `capture-state.json`에 기록합니다. 기존 출력이 있으면 `--resume` 또는 다른 출력 폴더를 요구하고 책 ID나 판본이 다른 상태를 섞지 않습니다. 재개 시 자산 목록은 실제 저장 파일에서 다시 읽습니다. 일부 구간을 재사용했다고 이전 자산이 보고서에서 사라져서는 안 됩니다.

상태 파일 자체는 원자적인 체크포인트 형식이 아닙니다. 비정상 종료로 JSON이 잘렸다면 지우고 덮어쓰기부터 하지 말고 복사본과 실제 XHTML 및 자산을 확인합니다. 재개도 로그인된 리더와 판본 확인이 필요합니다. 로그인 없이 할 수 있는 작업은 저장 자료의 검증과 재생성입니다.

패키저는 출력 폴더 안의 허용된 파일을 검사하고 XML, 참조 대상, 중복 ID, 외부 의존성, 누락된 각주와 CSS import를 확인합니다. EPUB 출력은 콘텐츠 폴더 밖에 둡니다. ZIP의 첫 항목은 압축하지 않은 `mimetype`이며 manifest, spine, EPUB 탐색 문서와 NCX를 생성합니다. 임시 ZIP을 검증한 뒤 최종 파일을 교체합니다.

패키저의 허용 MIME과 추출기의 입력 형식 목록은 서로 다를 수 있습니다. 새 이미지 형식을 지원하려면 EPUB 호환성과 원본 보존 방식을 함께 정합니다. ZIP 생성 성공과 EPUB 규격 적합성은 별도 검사입니다.
