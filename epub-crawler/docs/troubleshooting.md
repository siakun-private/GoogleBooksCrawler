# 문제 해결과 운영 요령

## Orca 연결이 실패할 때

설치된 `orca-cli` 스킬에서 실행 파일 선택 규칙을 읽고 그 바이너리의 `skills get orca-cli` 가이드를 사용합니다. `status --json`과 `tab list --json`으로 앱 상태 및 정확한 탭을 확인합니다. 외부 Chrome과 Orca 내장 브라우저는 다른 조작 대상입니다.

공개 브라우저 명령이 응답하지 않아도 앱이 종료됐다고 단정하지 않습니다. 탭 URL이 일치하는 로컬 프록시가 존재하면 코드의 CDP 경로로 검사할 수 있습니다. `/json/list`로 대상을 확인하지 않은 포트에는 연결하지 않습니다. 기존 명령의 실패를 이유로 Orca 전체나 다른 작업자의 터미널을 종료하지 않습니다.

본문 프레임이 없다는 오류가 나면 리더 로딩, OOPIF 대상과 attach 이벤트를 확인합니다. 필요한 순서는 `browser.py`에 있습니다. 메인 문서의 Runtime 세션에서 본문용 Blob을 fetch하는 것과 본문 세션에서 메인 문서의 메타데이터를 찾는 것은 서로 다른 오류입니다.

## 구간이 없거나 내용이 다를 때

현재 책 ID와 판본이 저장 상태와 일치하는지 봅니다. 구간의 페이지 번호가 아닌 `start_position`으로 이동했는지 확인합니다. 화면에 노출된 `.gb-segment`처럼 보여도 분할 속성이 붙은 페이지 조각이면 원본 후보가 아닙니다.

글자 수 차이가 나면 UTF-16 계산과 원본 구간 선택을 먼저 확인합니다. UI의 `innerText`는 숨김 요소와 줄바꿈에 영향을 받으므로 캡처 검사의 `textContent`와 같은 기준이 아닙니다. 저장한 텍스트를 조용히 보충하거나 문장 끝을 추정해서 이어 붙이지 않습니다.

## 이미지와 글꼴

URL의 서명이나 Blob 주소는 다음 세션의 다운로드 주소가 아닙니다. 브라우저를 다시 연결해 실제 원본 참조를 읽습니다. 원본 URL의 폭 파라미터를 크게 했을 때 이미지 픽셀 수만 늘었다면 실제 선명도 개선은 미확인 상태입니다. 본문에 지정된 원본 바이트 보존이 기본입니다.

브라우저의 font 상태가 `unloaded`라고 모두 오류는 아닙니다. 현재 구간에서 쓰지 않은 글꼴은 로드되지 않을 수 있습니다. 사용하는 글꼴의 상태와 화면을 함께 봅니다. 표지는 일반 `img`가 아니라 SVG `image`일 수 있어 이미지 개수 검사에서 빠뜨리지 않습니다.

## 뷰어 수정이 보이지 않을 때

원본 `reader` 파일을 고친 뒤 `html_reader.py`를 실행했는지 확인합니다. 파일 URL을 연 브라우저가 예전 문서를 캐시하면 일반 새로고침만으로 이전 스크립트가 남을 수 있습니다. 캐시를 무시하는 새로고침을 사용하고 생성 HTML에 바꾼 코드가 들어 있는지 먼저 확인합니다.

하단 위치가 틀리면 원본 페이지 번호, 구간 번호, 화면의 단 번호를 구분합니다. 소수점 단 폭, 빈 페이지 앵커, 설정 변경 직후의 글꼴 로딩도 검사합니다. UI 범위를 항상 시작 페이지에 1을 더하는 방식으로 만들지 않습니다.

## 파일 이동과 검사 도구

폴더 이동은 상대 경로 구조를 통째로 유지하고 이동 전후 파일 해시를 비교합니다. 실행 중인 EPUB 앱이 파일을 잠근 경우에는 동일한 사본을 새 위치에 먼저 보존하고 잠금이 풀리기 전 원본 삭제를 강행하지 않습니다. 부분 이동 실패 뒤에는 폴더 존재 여부만 보지 말고 파일별 실제 위치를 확인합니다.

PowerShell의 Java 시스템 속성은 `'-Dfile.encoding=UTF-8'`처럼 인자 전체를 따옴표로 감쌉니다. 한글 이름이 콘솔에서 깨져도 결과 파일의 UTF-8 JSON을 직접 읽어 검사 결과를 확인합니다. EPUBCheck 설치본은 프로젝트 입력 자료와 분리하고 명령에는 실제 JAR 경로를 전달합니다.

`output` 안의 임시 검증 스크립트는 과거 탭 주소나 특정 책 조건을 포함할 수 있습니다. 재사용할 검사는 `tools/verify_reader.py`와 [검증 절차](validation.md)를 사용합니다. 스크린샷 응답의 base64 전체를 로그에 출력하지 말고 로컬 PNG로 저장한 뒤 확인합니다.

## 작업자 분담

브라우저 구간 탐색은 한 작업자에게 맡깁니다. 별도 작업자는 저장된 XHTML의 검증, EPUB 생성이나 UI 원본처럼 충돌하지 않는 파일을 맡을 수 있습니다. 작업자에게 입력 경로, 담당 파일, 완료 조건과 출력 경로를 함께 전달합니다.

완료 메시지와 프로세스 종료를 산출물 완료로 취급하지 않습니다. 파일 존재와 검사를 확인한 뒤 통합합니다. 컨텍스트가 지나치게 작아 작업자가 코드를 남기지 못하면 범위를 더 작게 나누거나 주 작업자가 이어받습니다. 빠른 판단 도구는 이미 확보한 검사 결과의 선택에 쓰며 실제 브라우저 검사나 파일 확인을 대신하지 않습니다. 종료 확인이 불명확하면 해당 작업자만 조사하고 터미널 전체 종료로 정리하지 않습니다.
