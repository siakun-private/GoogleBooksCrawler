# HTML 읽기 화면

뷰어는 인터넷이나 로컬 서버 없이 `file://`로 여는 화면입니다. 생성기는 `html_reader.py`, 원본 조작부와 본문 스타일 및 동작은 `reader` 안에 있습니다. 생성 파일을 직접 편집하면 재생성 때 사라지므로 원본을 수정합니다.

## 본문을 넣는 방법

모든 구간의 마크업과 탐색 정보를 실행되지 않는 JSON으로 HTML에 넣습니다. 로컬 파일 간 `fetch`에 의존하지 않으므로 브라우저의 파일 CORS 제약을 피할 수 있습니다. 이미지와 글꼴은 내장하지 않고 콘텐츠 폴더의 상대 경로를 유지합니다. 배포나 이동 시 `content` 폴더 전체가 필요합니다.

활성 구간은 `iframe.srcdoc`에 넣고 그 구간의 원래 XHTML 위치를 base URL로 삼습니다. 출판사의 CSS는 iframe 안에서만 적용해 메뉴의 스타일과 충돌하지 않게 합니다. 장 내부와 장 사이 링크는 부모 뷰어가 목적지로 연결하고 외부 참고 링크는 별도 창으로 엽니다.

원본 XHTML의 `<a/>`를 그대로 HTML로 해석하면 뒤따르는 내용까지 링크가 감쌀 수 있습니다. 생성기는 HTML 직렬화로 빈 앵커의 닫는 태그를 만듭니다. JSON 안의 `<`도 이스케이프해 책의 문자열이 script 태그를 끝내지 못하게 합니다. 이 경계는 [회귀 검사](../test_export.py)에 포함됩니다.

## 페이지와 읽던 위치

화면은 현재 구간을 CSS 다단으로 배치합니다. 자동 레이아웃은 창 폭에 맞춰 한 단 또는 두 단을 선택하며 사용자가 직접 선택할 수도 있습니다. 이전/다음 버튼은 화면 분량을 넘기고 구간 끝에서 다음 구간으로 이어집니다. 원본 페이지로 본문을 잘라 다시 합치는 방식은 사용하지 않습니다.

원본 페이지와 목차는 GBS 앵커로 이동합니다. 하단의 범위는 실제 화면에 걸치는 원본 페이지를 나타내므로 글자 크기와 창 크기에 따라 달라집니다. 같은 위치의 연속된 빈 페이지 앵커도 있을 수 있어 명시적으로 선택한 페이지가 범위에서 빠지지 않게 합니다.

빈 `display:none` 래퍼 안에 있는 위치 앵커는 좌표를 얻기 위해 표시 대상으로 바꿉니다. 본문이나 이미지를 감춘 요소까지 일괄 표시하지 않습니다. 단의 이동 폭은 소수점이 있는 `getBoundingClientRect().width`로 계산합니다. `clientWidth`의 정수 반올림은 긴 구간에서 오차가 누적돼 경계의 앵커가 화면 밖으로 밀릴 수 있습니다.

설정 변경과 창 크기 변경 후에는 글꼴 로딩을 기다리고 단 위치를 다시 측정합니다. 기존 단 번호를 재사용하는 대신 읽던 앵커로 복원합니다. 제목 상자의 `break-inside`도 살펴 빈 색상 상자와 제목이 서로 다른 단으로 갈라지는지 확인합니다.

## 설정과 검색

테마, 글꼴, 글꼴 크기, 행 간격, 정렬, 레이아웃, 북마크와 읽던 위치를 책 ID별 localStorage에 저장합니다. 저장소 키와 기본값은 `reader.js`에서 관리합니다. 저장소 사용이 거부돼도 현재 창의 읽기는 계속하며 다음 방문 때 복원되지 않을 수 있습니다.

검색은 본문 마크업에서 텍스트를 모읍니다. 문장 안에 있는 위치 앵커 때문에 검색어를 중간에서 나누지 않습니다. 검색 결과는 구간과 앵커로 이동하고 화면에서 일치하는 부분을 강조합니다. 여러 텍스트 노드에 나뉜 문자열의 강조와 검색 결과의 범위가 같다고 가정하지 말고 변경 시 함께 확인합니다.

## UI 변경 후 확인

밝은 테마와 어두운 테마에서 표시 옵션의 선택/비선택 상태, 목차 계층과 활성 행, 북마크 추가/삭제, 검색 이동을 확인합니다. 하단 슬라이더 미리보기와 직접 페이지 입력도 검사합니다. 좁은 창에서는 메뉴와 하단 범위가 잘리지 않아야 합니다.

새로고침 후 설정과 위치를 복원하고 글꼴 변경 후에도 읽던 문단 근처가 보이는지 확인합니다. 표지의 SVG 이미지, 장 사이 각주, 긴 코드와 표를 포함해 검사합니다. 모든 원본 페이지와 목차 목표가 표시 영역 안에 들어오는지는 [검증 절차](validation.md)의 브라우저 검사로 확인합니다.
