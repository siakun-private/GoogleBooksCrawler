# EPUB 크롤러 작업 지침

새 세션은 [인수인계 시작점](docs/handoff.md)을 읽고 필요한 문서로 이동합니다. 실행은 이 폴더를 기준으로 합니다. [README](README.md)의 빠른 시작을 사용하고 동작을 바꾸기 전에 [추출 구조](docs/extraction.md)와 [HTML 뷰어](docs/reader.md)의 보존 조건을 확인합니다.

페이지가 분할되기 전의 본문을 저장하는 것이 핵심입니다. 화면에 보이는 페이지 조각을 합치거나 스크린샷/OCR로 바꾸지 않습니다. 완전한 구간을 찾지 못하면 원인을 확인하며 부분 결과를 완성본으로 보고하지 않습니다.

본문, 이미지와 글꼴은 `output`에 보관합니다. 이 디렉터리는 Git에서 제외합니다. 원본 이미지를 재압축하거나 픽셀 확대만으로 고해상도 원본을 복원했다고 주장하지 않습니다. 로그에 인증 정보나 서명된 리소스 URL을 남기지 않습니다.

Orca 브라우저 조작은 설치된 `orca-cli` 스킬과 해당 실행 파일이 제공하는 가이드를 먼저 읽습니다. 이미 로그인된 책 탭을 사용하며 인증 쿠키를 별도 파일로 내보내지 않습니다. 탭 ID, 포트, 프레임 세션 ID는 실행마다 다시 찾습니다. `browser.py`의 대상 URL 검사를 생략하지 않습니다.

HTML 뷰어를 고칠 때는 `reader`의 원본과 `html_reader.py`를 수정한 뒤 다시 생성합니다. `output/content/index.html`을 직접 고쳐 끝내지 않습니다. EPUB 문서에 뷰어 JavaScript를 넣지 않습니다. 페이지 번호는 원본 앵커, 넘김은 화면 분량이며 하단에는 실제 보이는 원본 페이지 범위를 표시합니다.

자료가 이미 저장돼 있으면 UI 수정이나 패키징 검사를 이유로 다시 수집하지 않습니다. 필요한 검사는 [검증 절차](docs/validation.md)를 따릅니다. 결과의 개수와 현재 상태는 생성 보고서에서 읽고, 예전 보고서가 새 수정도 검증했다고 해석하지 않습니다.

브라우저 연결 실패와 코드 실패를 구분합니다. [문제 해결](docs/troubleshooting.md)에 따라 복구하고 다른 작업의 탭이나 터미널을 일괄 종료하지 않습니다. 여러 에이전트를 쓴다면 파일 소유 범위를 나누고 같은 책 탭의 조작은 한 작업자에게만 맡깁니다.
